# Проверка объединённых компонентов

Проверено 23 сентября 2026 года в Linux, Python 3.12.14. Проверяемая ветка — `feature/backend-filtering` (PR #2), с модулем объяснений участника 2 из `main` и исправлениями интеграции.

## Результат

- `python -m pytest -q`: **100 passed in 2.75s**.
- `python -m pip check`: **No broken requirements found**.
- Реальный Uvicorn запущен локально. `/health` подтвердил 66 профилей; все 6 сценариев прошли через HTTP `/recommendations` и дали ровно ожидаемые карточки.
- Неправильный бюджет вернул HTTP 422. Бизнес-исходы A/B/C вернули HTTP 200.
- На шести локальных запросах без ключа время ответа составило 1.418–6.453 мс после старта сервера. Измерения сохранены в `docs/integration-results.json`.

## Что проверяют тесты

- Все фильтры, границы бюджета и длительности, пустое `max_hours`, несколько языков, занятые даты, точность города и категории.
- Воспроизводимость сортировки, максимум 5 кандидатов / 3 карточки, пересекающиеся причины исключений.
- 200 фиксированных случайных запросов в сравнении с независимым прямым отбором.
- Одинаковые данные из CSV/JSONL: 66 записей, 13 synthetic, 8 city_imputed, 18 price_imputed, 9 max_hours=null.
- Путь HTTP API → фильтр → `LLMExplainer` → настоящий OpenAI SDK → имитация HTTP для OpenAI и NVIDIA.
- Правильный адрес провайдера, статус, выбранные ID, передача даты, цены, языков и длительности.
- Успешные ответы, кеш, сохранение ID/порядка/флагов, ответ в другом порядке ключей JSON.
- Ошибка 429, сетевой таймаут, неверный JSON, неправильный статус, чужие ID, запрещённые клише.
- Ошибки не кешируются; следующий запрос может успешно получить объяснение.
- При B/C запрос к модели отсутствует, а проверенное сообщение с причинами сохраняется.
- Общий таймаут: медленный вызов продолжает ждать в рабочем потоке, а API уже возвращает исходные карточки. Для теста используется лимит 0.1 секунды вместо рабочих 8 секунд.
- Загрузка `.env` и приоритет системных переменных. Тесты изолированы от настоящих ключей и прокси окружения.

## Исправления при объединении

1. API раньше вызывал только фильтры. Теперь подключён `RecommendationService`, вызывающий модуль участника 2.
2. Имена полей двух модулей согласованы через адаптер.
3. Добавлены общий таймаут, резервные тексты и явная метка источника объяснений.
4. Общий кеш LLM заменён кешем экземпляра с блокировкой; резервные ответы больше не запоминаются как успешные.
5. Добавлены необходимые зависимости и чтение `.env`. SDK не повторяет запросы автоматически, длина ответа ограничена.

## Воспроизведение

```bash
python -m pip install -r requirements-lock.txt
python -m pytest -q
python -m pip check
python -m uvicorn api:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/docs` и отправьте любой `examples/*_request.json` в `/recommendations`.

## Что ещё не проверено

- `app.py` отсутствует во всех трёх ветках команды; целый пользовательский путь Streamlit пока запустить невозможно.
- Настоящие OpenAI/NVIDIA не вызывались: ключи не настроены. Имитация проверяет соединение кода, но не доступность модели, баланс, качество её текстов или скорость внешнего сервиса.
- Лимит ожидания 8 секунд проверен механизмом сокращённого таймаута. Целевые <10 секунд для всего приложения при реальной сети и нагрузке ещё не подтверждены. Уже отправленный запрос может продолжиться у провайдера после возврата резервного ответа.
- Проверка формы ответа не доказывает достоверность всех фактов свободного текста LLM.
- Windows непосредственно не тестировался. Google Docs был недоступен; правила фильтрации взяты из предоставленных PDF и CSV.
- Изменения находятся в PR #2; в `main` они появятся после принятия PR командой.
