# HackAlem — бэкенд участника 1

Готовая часть проекта «Умный подбор подрядчиков (#79-lite)»: чтение данных, строгие фильтры, воспроизводимое ранжирование, три исхода, диагностика исключений и контракт для LLM/Streamlit.

Реализовано по приложенному PDF и исходному CSV из 66 профилей. Google Docs по переданной ссылке оказался недоступен; дополнительные требования из него не проверены. Исходный HTML использован для сверки описания календаря. Данные не расширялись и не исправлялись вручную.

## Быстрый запуск без установки библиотек

Нужен Python 3.10 или новее. Проверено на Python 3.12. Распакуйте архив и откройте терминал **в папке с `main.py`**.

Windows:

```powershell
py demo.py
py main.py validate
py main.py search --request examples/01_dense_request.json
```

macOS/Linux: замените `py` на `python3`.

`demo.py` показывает шесть готовых запросов, включая три обязательных сценария и отдельные случаи B/C. Для демонстрации своего бэкенда API-ключи и интернет не нужны. Это демонстрация фильтров без сети. HTTP API дополнительно вызывает модуль объяснений участника 2, если настроен ключ.

## Как работает пайплайн

CSV/JSONL читается в неизменяемые профили. Запрос проверяется до отбора. Затем выбираются точные город и категория, проверяются дата, бюджет, формат, языки и длительность. Прошедшие профили сортируются по `(price_from_kzt, id)` по возрастанию. Первые 5 попадают в `candidates`, первые 3 — в `cards` и `llm_context.selected_ids`.

В ядре фильтрации одинаковые данные и запрос дают одинаковый полный результат. Внешняя LLM может менять формулировки; набор и порядок карточек остаются фиксированными. В ответе нет случайного выбора, текущего времени или нестабильных метрик. Изменение порядка строк CSV не меняет результат. Хеш `dataset_version` рассчитывается по нормализованным данным, включая описания и календари.

Цена используется как прозрачное правило сортировки, а не оценка качества. Из дешёвой или дорогой цены не делаются выводы о профессионализме. Языки при их указании — обязательный фильтр, поэтому не используются повторно как формальный балл ранжирования.

## Точные правила

| Условие | Правило |
|---|---|
| Город | Точное равенство `city` после удаления пробелов по краям |
| Категория | Точный элемент `categories`, не поиск подстроки |
| Дата | Даты нет в `busy_dates` |
| Бюджет | `price_from_kzt <= budget_kzt`, граница включается |
| Формат | Точный элемент `event_formats` |
| Языки | Все переданные `languages` присутствуют в профиле; `[]` отключает фильтр |
| Длительность | `duration_hours <= max_hours`, если указаны оба значения |
| `max_hours=null` | По PDF услуга не привязана к присутствию; не исключаем по длительности |
| Дата вне окна | Ошибка ввода, а не утверждение о свободной дате |
| Флаги данных | `synthetic`, `city_imputed`, `price_imputed` сохраняются в кандидатах и карточках |

Календарь известен только для **2026-09-23 — 2026-12-31 включительно**. Значения «Астана» и «Алматы» не заменяются друг другом. Регистр не исправляется: для UI берите значения из `/options`.

Начальная цена не равна гарантированной итоговой стоимости. `synthetic=false` означает исходный анонимизированный профиль, а не проверку реальности личности. Для профилей с дополненной ценой или городом возвращаются соответствующие флаги и примечания.

Повреждённые записи не пропускаются молча: загрузчик сообщает файл, строку и причину. Дубликаты ID, неверные даты, отрицательные цены, строковые JSON-флаги и неправильные списки отклоняются. В CSV списки разделены `|`, `True/False` явно преобразуются в bool, пустые часы — в `null`.

## Три исхода и причины

| `status` | `outcome` | Смысл |
|---|---|---|
| `ok` | A | Есть подходящие профили |
| `no_category_in_city` | B | В датасете нет этой категории в этом городе |
| `no_matches` | C | Категория в городе есть, но никто не проходит все условия |

Все три бизнес-исхода возвращают HTTP 200. Неверные параметры возвращают HTTP 422. CLI для ошибки ввода/данных завершает работу с кодом 2.

В `excluded` есть ID и все причины исключения каждого профиля из пула «город + категория». В `summary.exclusions_by_reason` — соответствующие счётчики. Они **пересекаются**: один человек может одновременно быть занят и дороже бюджета. Число уникальных исключённых профилей находится в `excluded_profiles`. Город и категория применяются до этих счётчиков.

Если найдено меньше трёх, выдаётся фактическое количество. Сообщение указывает исходный размер категории в городе, остаток и причины исключения. Недостающие карточки не заполняются неподходящими профилями.

## Подключение к app.py напрямую

```python
from src import FilterEngine, load_profiles

engine = FilterEngine(load_profiles())  # один раз при запуске
result = engine.search({
    "city": "Алматы",
    "date": "2026-10-10",
    "event_format": "корпоратив",
    "category": "Ведущий",
    "budget_kzt": 1500000,
    "languages": [],
    "duration_hours": None,
})
print(result["message"])
print(result["cards"])
```

Альтернативный простой интерфейс: `find_contractors(profiles, user_request)`. При повторных запросах предпочтителен один `FilterEngine`, чтобы не перечитывать и не хешировать данные каждый раз.

## OpenAI API, затем NVIDIA API

HTTP `POST /recommendations` уже соединяет `FilterEngine` с существующим `LLMExplainer` через `RecommendationService`.

1. Установите `requirements.txt` и скопируйте `.env.example` в `.env` рядом с `api.py`.
2. Для OpenAI оставьте `LLM_PROVIDER=openai` и заполните `OPENAI_API_KEY` локально.
3. Для NVIDIA выберите `LLM_PROVIDER=nvidia`, заполните `NVIDIA_API_KEY` и `NVIDIA_MODEL` моделью, доступной вашему аккаунту.
4. Перезапустите сервер. Запрос с карточками возвращает `explanation_status.source=external_llm`, если получен допустимый ответ модели.

В одном поиске вызывается только выбранный провайдер. Без ключа, при ошибке или ожидании дольше 8 секунд остаются фактические локальные подписи: `explanation_status.source=deterministic_template`. Поле `reason` сообщает причину. Автоматических повторов внешнего запроса нет. Для исходов B/C сетевой вызов пропускается: сообщение с точными числами уже рассчитано бэкендом.

Ядро `engine.search()` и консольные команды работают без LLM. Для полного пути используйте HTTP API или `await service.recommend(request)`. Подробности для интерфейса: [docs/TEAM_INTEGRATION.md](docs/TEAM_INTEGRATION.md).

LLM получает только три выбранных профиля, цену, дату, языки и длительность. Проверяются статус, набор ID, длина, число предложений, запрещённые клише и повторяющиеся тексты. Проверка формы не доказывает достоверность каждого факта свободного текста. Нейросеть не может менять кандидатов, сортировку и метки синтетических/дополненных данных.

Успешные ответы кешируются в памяти конкретного экземпляра; ошибки и ответы без ключа не кешируются. После перезапуска формулировки могут отличаться даже при `temperature=0`. Лимит ожидания 8 секунд оставляет запас до целевых 10 секунд, но скорость настоящего провайдера и всего интерфейса без ключей и `app.py` не проверялась. Уже отправленный запрос может завершиться у провайдера после возврата локальных карточек.

Настоящие ключи не включены и не должны попадать в Git. OpenAI и NVIDIA проверены с настоящим SDK и имитацией HTTP-ответа, без обращения к внешним моделям. На момент проверки `app.py` отсутствует во всех ветках команды.
